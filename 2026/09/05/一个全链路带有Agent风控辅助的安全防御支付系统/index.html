一个全链路带有Agent风控辅助的安全防御支付系统

S12lx0 Lv1
  2026-09-05 14:00 2026-09-05 14:00 Created   2026-09-06 13:32:56 2026-09-06 13:32:56 Updated  

这是一个从代码开发、安全防御到容器化部署的全链路支付系统项目实践，重点展示Web安全防御能力、Java工程、Agent风控结合、Redis缓存应用、JWT身份认证、接口限流、审计日志、手机号数据脱敏、Linux服务加固与Docker容器化部署等多个技术板块。以Spring-Boot为架构，Lombok简化代码，MyBatis+MySQL进行数据访问，BCrypt+AES-GCM进行密码与数据加密，采用DeepSeek API作为风控决策引擎，Redis实现验证码缓存与订单频次控制模拟真实业务环境，最终在Postman完成接口测试

项目选择

在传统支付设计中，功能实现一般为三步走——用户注册、下单、扣款，但在真实的支付环境中，作为安全学习者必须对多个核心安全问题敏感：

  • 安全风险： SQL注入、XSS、数据泄露

  • 业务风险： 大额异常交易、刷单攻击

  • 工程风险： 未授权访问、越权操作、用户敏感信息如手机号泄露、外部root攻击、开发环境不匹配导致的配置冲突

在此基础上，AI大时代下引入了Agent进行智能风控管理。以上是整个支付系统的核心业务逻辑，后续对该系统进行Linux服务加固与Docker容器化实现开发环境与生产环境一致性迁移，最终本人完成一个带有Agent风控辅助的具备纵深防御能力全链路个人项目构建。本文着重说明Java核心业务，Linux与Docker在后续描述。

整体架构

用户在支付前，Agent先判断风险等级，判定低危才执行扣款与生成订单

  • 表现层Controller：接收HTTP请求，参数校验与响应封装

  • 业务层service：风控判断、支付处理、用户管理、短信验证、审计日志

  • 数据层mapper：数据库增删改查操作

  • 实体层entity：与数据库表结构对应的java对象

  • 安全层filter：XSS防御过滤器

  • 安全层增强组件：JWT认证拦截器、接口限流拦截器、手机号数据脱敏

创建项目

用Spring Initializr生成Spring Boot框架，填写项目基本信息与添加依赖

https://start.github.io

注：由于本人是边做边升级，一些依赖都在后续进行了手动添加，这里完整应该加入Spring Boot Starter Data Redis、JJWT、OkHttp、Jackson、Spring Security Crypto、Guava依赖，项目确实应该一开始想好整体做，边做边升级虽然说是可以手动添加，但偶尔会出现版本号与依赖不存在问题，要去Maven官方进行搜索，还是有点麻烦

Spring Boot只能选择4.0.8，MyBatis的依赖添加要在版本4.0.0~4.1.0

  • Spring Web：提供Web层（Controller、RestController等）接收分发请求，内置Tomcat

  • MyBatis Framework：数据库ORM框架，把SQL查询结果映射成Java对象，同时把Java转换成SQL参数，以便用Java代码操作数据库；MyBatis能通过预编译防止SQL注入

  • MySQL Driver：MySQL数据库驱动，实现Java与MySQL之间的数据转化，把Java数据库请求翻译成MySQL执行命令，将MySQL返回结果翻译成Java能读数据

  • Lombok：简化实体类代码（自动生成getter/setter）

  • Spring Boot DevTools：热部署，改完代码不用手动重启，提升开发效率

项目总结

项目越做到后面，我越觉得一个项目的核心不只是代码能跑，一开始的逻辑设计是否清晰也尤为重要。最开始确实是打算做一个简单的支付功能，做着做着就开始思考这里能否加层安全防御，有没有可以升级的地方。比如注册流程中，手机号是否需要验证，返回的 JSON 里手机号是否需要做脱敏，登录时怎么保证用户身份唯一性，能否用 JWT 来替代传统Session 管理，这些问题不是一开始就想到的，而是在写代码的过程中不断思考优化出来的。

另外，借着这次项目也第一次把 AI 能力接进了业务——用 DeepSeek API 做风控辅助，虽然只是初步尝试，但确实让我对”AI 怎么落地到实际工程”有了点实感。越往下做，越发现安全不是一个点，而是进行一层层安全防御叠加出来的。

不过坦白说，边做边加功能确实挺折腾，时不时遇到版本不兼容的问题，比如 Spring Boot 升级后某些依赖就得重新找版本。但这些”麻烦”反而让我对 Spring Boot 的依赖管理、各层之间的调用关系有了更实在的理解。

整体来看，这次项目在核心 Java 工程和代码层面的安全防御、AI 辅助判断就告一段落了。剩下的 Linux 安全加固和 Docker 部署在后续里单独说明。
